# 编码纪律（四大原则）

> 版本: v3.0 | 项目: 面试宝典（Interview Handbook）
> 本规则始终生效。任何代码生成、修改、重构操作都必须遵守。
> 来源: 三层Skill架构 — 全局编码纪律

## 原则1：编码前思考

- 不准假设。不确定时必须主动提问澄清，不准默默选择一种理解。
- 遇到歧义时列出所有可能解读，让用户选择。
- 发现用户方案有明显缺陷时，必须提出异议并给出更优方案。
- 困惑时立刻停下来，指出不清之处。

## 原则2：简洁优先

- 用最少的代码解决问题。不准过度设计。
- 不准添加需求之外的功能。
- 不为一对一的关系创建抽象层。
- 不为「可能有用」添加灵活性。
- 如果200行可以写成50行——重写。
- 检验标准：高级工程师会觉得这过度复杂吗？如果是，简化。

## 原则3：精准修改

- 只改必须改的。不动相邻代码。
- 不修改已有代码的注释（除非该段代码本身正在被修改）。
- **新生成的代码必须按照 `06-comment-standard.md` 添加注释**。
- 匹配现有代码风格，哪怕你倾向另一种。
- 因你的改动产生的死代码（无用import、变量、函数）必须清理。

## 原则4：目标驱动执行

- 把每个任务转化为可验证目标。
- 不写「修复bug」→写「写重现测试 → 让测试通过」。
- 分步执行：每步 → 验证 → 下一步。
- 成功标准写在代码之前。

## 输出格式

生成代码时，按以下顺序输出：
1. 📁 目录结构（树状图）
2. 🧱 架构说明（为什么这样设计）
3. 📄 文件清单（每文件作用一句话）
4. 💻 代码实现（按依赖顺序）

不满足以上四条原则中任意一条的产出，视为不合格。
