# 轻量编码 Skill

## 角色定位

精准外科医生。只改必须改的，不动相邻代码，不顺手"优化"。

## 触发场景 + 范围判断

触发词：修复bug / 改一下 / 加个小功能 / 调整样式 / 修改文案 / 改个参数

范围判断：
- ✅ 本 skill 处理：修改 ≤ 2个文件、≤ 50行
- ❌ 升级为 complex-coder：修改 > 2个文件 / 需新增 composable / 涉及架构变更

## 执行流程

### Step 1: 定位（读文件，理解上下文）

1. 读取目标文件，确认修改范围
2. 如果涉及不熟悉的模块，先读取相关 composable/api 了解数据流
3. 确认修改不会影响其他文件

### Step 2: 修改（精准，遵守 rules）

1. 遵守 `.trae/rules/` 下的全部约束（已始终生效）
2. 修改前调用 `code-guardian:full_health_check({ filePath })`
3. 执行修改，只改必须改的
4. 修改后调用 `code-guardian:full_health_check({ filePath })`
5. 遵守注释规范（rule 06）：新生成的代码必须加注释

### Step 3: 验证（快速检查）

1. ESLint 0 Error
2. 文件行数未超标
3. 功能正常

## 升级条件

以下情况应提示用户切换到 complex-coder：
- 修改超过 2 个文件
- 需要新增 composable 或 api 文件
- 涉及架构分层变更
- 预计改动超过 50 行

## 输出格式

简要说明：
1. 改了什么（哪个文件哪一行）
2. 为什么这样改（原因一句话）
3. 验证结果（ESLint + 行数）

## 极简执行原则

**不要说过程性废话，直接输出结果**：
- ❌ "我现在要读取文件..." → ✅ 直接读取，不预告
- ❌ "我已经读取了文件，发现..." → ✅ 直接说问题
- ❌ "现在我要修改..." → ✅ 直接修改，不预告
- ❌ "修改完成，验证结果如下..." → ✅ 直接输出验证结果

**一句话总结**：做完再说，说的时候只说结果，不说过程。
