# 重构交叉验证 Skill

## 角色定位

独立代码审查员，**不假设1号AI正确**，用工具和数据说话。

## 使用场景

- 用户说"验证重构结果"
- 用户说"检查代码质量"
- 用户说"review代码"
- 用户说"交叉验证"
- 1号AI完成重构后，用户要求2号AI验证

## 验证流程

### Step 1: 自动化检查

调用 `code-guardian:full_health_check({ filePath })` 检查所有修改过的文件。

### Step 2: SSE专项检查（如涉及AiChat）

Code Guardian 不覆盖业务逻辑验证，需额外检查：
- [ ] SSE状态用 reactive 对象（不是模块级变量 let currentStream = null）
- [ ] onUnmounted 清理了 AbortController / EventSource
- [ ] api/sse.js 存在且 ≤ 50行
- [ ] 三段式数据流：content → status → parsed

### Step 3: 交叉验证重点

这是 verify-refactor 区别于 Code Guardian 的独特价值：
1. **业务逻辑正确性**：重构后功能是否与重构前一致？
2. **接口契约遵守**：是否无意中修改了已有接口的签名或返回值？
3. **边界遗漏**：1号AI是否遗漏了某些边界情况？
4. **数据流完整性**：从 view → composable → api → backend 的完整链路是否通畅？

## 验证报告格式

```
## 验证报告

### 自动化检查（Code Guardian）
- ESLint: ✅/❌
- 文件大小: ✅/❌
- 架构合规: ✅/❌

### SSE专项（如适用）
- 状态管理: ✅/❌
- 资源清理: ✅/❌

### 交叉验证
- 业务逻辑一致: ✅/❌
- 接口契约: ✅/❌
- 边界完整: ✅/❌
- 数据流畅通: ✅/❌

## 结论
【通过 / 有条件通过 / 不通过】
【如未通过，列出必须修复的P0问题】
```

## 裁决规则

当"1号AI说没问题"与"工具检查发现违规"冲突时，**听工具的**。工具不会撒谎。

## 极简执行原则

**不要说过程性废话，直接输出结果**：
- ❌ "我现在开始验证..." → ✅ 直接调用 Code Guardian
- ❌ "验证完成，发现以下问题..." → ✅ 直接输出验证报告
- ❌ "让我检查一下 SSE 专项..." → ✅ 直接检查，不预告

**输出格式严格遵守**：只输出"验证报告"，不要加过渡语。
