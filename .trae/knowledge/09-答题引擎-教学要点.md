# 模块5：答题引擎 — 教学要点

## 设计思路

- 为什么拆成useQuiz + useTimer两个composable？→ 单一职责，倒计时逻辑和答题逻辑互不耦合
- 为什么答案用 `{[qid]: [0, 2]}` 结构？→ 统一单选和多选的存储，calcScore可以统一处理
- 为什么用 `Promise.all` 而不是循环 await？→ 并行请求 N 个题目，总耗时是 max(latency) 而不是 sum

## 数据流

```
选题（筛选/搜索）→ 点击"开始答题" → URL带ids参数 → useQuiz.loadQuestions → Promise.all并行获取题目 → 逐题展示 → 用户选择 → userAnswers更新 → 提交 → calcScore打分 → submitRecord保存后端 → 跳转结果页
```

## 面试模拟

- Q: "怎么支持单选和多选？" → 通过题目的type字段区分，单选/判断直接替换 `[index]`，多选用数组toggle
- Q: "倒计时归零后怎么自动提交？" → useTimer暴露isTimeout computed，Quiz页watch它，触发handleSubmit(force=true)跳过二次确认
- Q: "怎么防止快速点击重复提交？" → submitted标志位，提交后禁用所有选项点击
