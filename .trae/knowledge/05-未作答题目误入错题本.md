# 未作答题目误入错题本

> 来源: `specs/fix-unanswered-in-wrong-book`
> 标签: #错题本 #数据过滤 #null处理 #连续正确
> 日期: 2026-06

---

## 问题根因

用户未作答的题目被错误计入了错题本，显示"你的答案：未记录"。

**直接原因**：后端 `getWrong` 接口的错题聚合逻辑遍历了所有 `details` 记录，**没有过滤 `isCorrect === null` 的未作答记录**。未作答的题目被当作"答错"处理，出现在错题列表中。同时 `calcConsecutive` 在遇到 `isCorrect === null` 时错误地将连续正确次数归零。

**深层原因**：三元状态（对/错/未作答）被当作二元状态（对/错）处理。`isCorrect` 有三个可能值：`true`（答对）、`false`（答错）、`null`（未作答），但代码只考虑了前两种，`null` 被隐式当作 `false` 处理。

**调用链**：
```
提交答题 → 后端保存记录（details 中 isCorrect: null, userAnswer: ''）
  → Dashboard 调用 getWrong → 遍历所有 details
    → isCorrect === null 的记录被当作错题 → 显示在错题本
```

---

## 解决方案

### 修复 1：getWrong 过滤未作答

`recordController.js` 的 `getWrong` 中，遍历 `details` 时跳过 `isCorrect === null` 的记录：

```js
// 修改前：遍历所有 details
for (const d of record.details) { ... }

// 修改后：只处理 isCorrect !== null 的记录
for (const d of record.details) {
  if (d.isCorrect === null) continue  // 跳过未作答
  ...
}
```

### 修复 2：calcConsecutive 不中断未作答

`calcConsecutive` 中，遇到 `isCorrect === null` 时保持上次连续正确次数不变：

```js
// 修改前：未作答也会中断连续
if (d.isCorrect === false) { consecutive = 0 }

// 修改后：未作答不中断，只有真正答错才中断
if (d.isCorrect === false) { consecutive = 0 }
// isCorrect === null → 不处理，保持上次值
```

**影响范围**：仅修改 `recordController.js`，前端 `stats.js` 已正确处理 `isCorrect = null`，无需修改。历史数据修复后读取时自动过滤。

---

## 如何避免再次发生

1. **三元状态必须有显式处理**：当字段有 `true`/`false`/`null` 三种可能值时，代码中必须显式处理每个分支，不能依赖隐式转换。`null` 和 `false` 在布尔上下文中行为相同，但语义完全不同。
2. **过滤逻辑要写清楚**：`if (isCorrect === null) continue` 比 `if (!isCorrect)` 更清晰，后者无法区分"答错"和"未作答"。
3. **"未记录"是一个危险信号**：如果数据显示"你的答案：未记录"，说明写入时就已经有问题。不要只在展示层修，要追溯到数据源头。
4. **统计口径要一致**：如果前端 `calcScore` 把未作答的 `isCorrect` 设为 `null`，后端所有消费 `isCorrect` 的地方都必须正确处理 `null`。这是一个跨前后端的契约，应该在注释中明确标注可选值。
