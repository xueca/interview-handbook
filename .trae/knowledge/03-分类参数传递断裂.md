# 分类参数传递断裂

> 来源: `specs/fix-dashboard-category-display`
> 标签: #路由参数 #数据流 #Dashboard #分类
> 日期: 2026-06

---

## 问题根因

用户从题库进入答题页后提交记录，Dashboard 的"分类正确率"和"薄弱知识点"均显示"未分类"。

**直接原因**：`category` 参数未从题库页传递到答题页。数据流断裂点：

```
QuestionBank.vue → router.push('/quiz')  ← 路由跳转未携带 category 参数
  → QuizPage.vue → useQuiz.js → handleSubmit()
    → 提交时 category 为空字符串
      → 后端保存记录时 category 为空
        → Dashboard 读取时显示"未分类"
```

**深层原因**：跨页面的数据传递依赖路由参数，但新增路由跳转时没有检查"所有需要的数据都传了吗"。这是一个典型的"数据流断裂"问题——上游有数据，下游需要数据，但中间连接断了。

---

## 解决方案

### 修复 1：路由跳转时携带 category

`QuestionBank.vue` 的两个跳转入口补上 `category` 参数：

- `goToQuiz()`（查看详情）：`router.push({ name: 'Quiz', query: { category: question.category } })`
- `startQuiz()`（批量答题）：`router.push({ name: 'Quiz', query: { category: selectedCategory } })`

### 修复 2：兜底获取

`useQuiz.js` 的 `handleSubmit()` 中增加兜底逻辑：若 `route.query.category` 为空，从 `questions[0].category` 获取。

**影响范围**：`QuestionBank.vue`、`useQuiz.js` 两个文件，不涉及后端。

---

## 如何避免再次发生

1. **新增路由跳转时，写一份"数据传递清单"**：列出目标页面需要哪些参数，确认每个参数都有来源。这是一个 30 秒的检查，但能避免 2 小时的排查。
2. **兜底策略必须写**：不能假设"上游一定会传"，下游必须有降级获取逻辑。这里的兜底是 `questions[0].category`，至少保证不丢数据。
3. **数据流要可追溯**：从哪个页面跳转来、携带了什么参数、谁消费了这些参数——在代码中用注释标注清楚。例如：
   ```js
   // 路由参数来源: QuestionBank.goToQuiz() → query.category
   const category = route.query.category || questions.value[0]?.category || ''
   ```
4. **Dashboard 数据异常时，先排查数据写入链路**：显示"未分类"不是 Dashboard 的问题，是写入时 `category` 就是空的。顺着数据流从展示 → 存储 → 提交 → 路由参数一路回溯，定位断裂点。
