## 二、第一层：自动化约束（机器强制执行）

### 2.1 ESLint 规则配置（立即生效）

**目标**：让 ESLint 在保存/构建时自动报错，强制遵守约束。

**需要安装的依赖**：
```bash
# 在前端目录执行
cd frontend
npm install --save-dev eslint eslint-plugin-vue
```

**`.eslintrc.cjs` 配置**（新建文件）：

```javascript
module.exports = {
  root: true,
  env: {
    browser: true,
    es2021: true,
    node: true
  },
  extends: [
    'eslint:recommended',
    'plugin:vue/vue3-recommended'
  ],
  parserOptions: {
    ecmaVersion: 'latest',
    sourceType: 'module'
  },
  rules: {
    // ===== 文件规模约束（硬限制）=====
    'max-lines': ['error', {
      max: 200,           // 单个文件不超过200行
      skipBlankLines: true,
      skipComments: true
    }],
    'max-lines-per-function': ['error', {
      max: 30,            // 单个函数不超过30行
      skipBlankLines: true,
      skipComments: true
    }],
    'max-params': ['error', 4],  // 函数参数不超过4个

    // ===== 反模式约束 =====
    'no-console': ['warn', { allow: ['error', 'warn'] }],
    // 禁止在 views 目录下直接 import axios（强制走 api 层）
    // 注：此规则需要自定义，见下方 2.2

    // ===== Vue 规范 =====
    'vue/multi-word-component-names': 'off',
    'vue/no-unused-vars': 'error',
    'vue/require-v-for-key': 'error',

    // ===== 代码风格 =====
    'indent': ['error', 2],
    'quotes': ['error', 'single'],
    'semi': ['error', 'never']
  },

  // 对特定目录放宽/收紧规则
  overrides: [
    {
      files: ['src/api/**/*.js'],
      rules: {
        'max-lines': ['error', { max: 50 }]  // api 文件不超过50行
      }
    },
    {
      files: ['src/composables/**/*.js'],
      rules: {
        'max-lines': ['error', { max: 150 }]  // composable 不超过150行
      }
    },
    {
      files: ['src/views/**/*.vue'],
      rules: {
        // views 目录下禁止直接 import axios
        'no-restricted-imports': ['error', {
          paths: [
            { name: 'axios', message: '视图层禁止直接引入 axios，请通过 api/xxx.js 调用' }
          ],
          patterns: [
            { group: ['**/utils/sse.js'], message: '视图层禁止直接引入 sse.js，请通过 composable 调用' }
          ]
        }]
      }
    }
  ]
}
```

**效果**：
- AiChat.vue 426行 → 保存时 ESLint 报错：`"max-lines"：文件超过200行`
- 任何函数超过30行 → 报错：`"max-lines-per-function"：函数超过30行`
- 视图层直接 `import axios` → 报错：`视图层禁止直接引入 axios`
- 视图层直接 `import sse.js` → 报错：`视图层禁止直接引入 sse.js`

### 2.2 自定义 ESLint 插件（架构分层约束）

**目标**：检测"视图层直接调用 fetch/axios/EventSource"这种架构违规。

**文件**：`frontend/eslint-plugin-architecture/index.js`

```javascript
// 自定义 ESLint 规则：禁止在 views 目录使用原生 fetch/EventSource
module.exports = {
  rules: {
    'no-direct-fetch-in-views': {
      meta: {
        type: 'problem',
        docs: {
          description: '禁止在 views 目录直接使用 fetch/EventSource',
          category: 'Architecture'
        },
        messages: {
          noDirectFetch: '视图层禁止直接使用 {{name}}，请通过 api/xxx.js 或 composable 调用'
        }
      },
      create(context) {
        const filename = context.getFilename()
        // 只检查 views 目录下的文件
        if (!filename.includes('/views/')) return {}

        return {
          // 检测 fetch() 调用
          CallExpression(node) {
            if (node.callee.name === 'fetch') {
              context.report({
                node,
                messageId: 'noDirectFetch',
                data: { name: 'fetch' }
              })
            }
          },
          // 检测 new EventSource()
          NewExpression(node) {
            if (node.callee.name === 'EventSource') {
              context.report({
                node,
                messageId: 'noDirectFetch',
                data: { name: 'EventSource' }
              })
            }
          }
        }
      }
    }
  }
}
```

**在 `.eslintrc.cjs` 中启用**：
```javascript
plugins: ['architecture'],
rules: {
  'architecture/no-direct-fetch-in-views': 'error'
}
```

### 2.3 Git Hooks（提交前自动检查）

**目标**：提交代码前自动运行 ESLint，有报错则阻止提交。

**安装**：
```bash
cd frontend
npm install --save-dev husky lint-staged
npx husky init
```

**配置 `package.json`**：
```json
{
  "lint-staged": {
    "*.{js,vue}": ["eslint --fix", "git add"]
  }
}
```

**`.husky/pre-commit` 钩子**：
```bash
#!/bin/sh
cd frontend
npx lint-staged
```

**效果**：
- 你修改了 AiChat.vue（426行）→ `git commit` → ESLint 报错 → 提交被阻止
- 必须先拆分文件或加 `// eslint-disable-next-line`（但后者会被 Code Review 发现）

### 2.4 后端文件行数检查脚本

**目标**：后端没有 ESLint 行数限制，用 Node.js 脚本检查。

**文件**：`backend/scripts/check-file-size.js`

```javascript
const fs = require('fs')
const path = require('path')

const LIMITS = {
  'controllers': 150,
  'routes': 50,
  'middleware': 80
}

let hasError = false

Object.entries(LIMITS).forEach(([dir, maxLines]) => {
  const dirPath = path.join(__dirname, '..', dir)
  if (!fs.existsSync(dirPath)) return

  fs.readdirSync(dirPath).forEach(file => {
    if (!file.endsWith('.js')) return
    const filePath = path.join(dirPath, file)
    const content = fs.readFileSync(filePath, 'utf-8')
    const lines = content.split('\n').length

    if (lines > maxLines) {
      console.error(`❌ ${dir}/${file}: ${lines}行 > ${maxLines}行限制`)
      hasError = true
    } else {
      console.log(`✅ ${dir}/${file}: ${lines}行`)
    }
  })
})

if (hasError) {
  process.exit(1)
}
```

**在 `backend/package.json` 中添加**：
```json
{
  "scripts": {
    "check-size": "node scripts/check-file-size.js"
  }
}
```

```
✅ controllers/authController.js: XX行
✅ controllers/questionController.js: XX行
❌ controllers/recordController.js: 289行 > 150行限制
```

### 3.3 AI Prompt 模板（放在手边）

**文件**：`.trae/prompt-templates/`（放在 Trae IDE 容易找到的位置）

**`anti-pattern-preface.md`**（每次让AI写代码前，复制这段）：

```markdown
## 反模式清单（以下做法绝对禁止）

❌ 禁止1：在组件 script 内直接写 API 调用（fetch/axios/EventSource）
❌ 禁止2：在组件内做超过3行的数据转换/计算逻辑
❌ 禁止3：async 函数不 catch 错误
❌ 禁止4：timerId/SSE/AbortController 不做 onUnmounted 清理
❌ 禁止5：一个文件超过200行不拆分
❌ 禁止6：函数超过30行不拆分

## 架构分层（必须遵守）

视图层(.vue) → Composable → API层(api/*.js) → 后端
- 视图层：只渲染 + 事件转发
- Composable：业务逻辑 + 状态管理
- API层：HTTP通信，不处理业务

## 文件规模限制

- .vue 文件 ≤ 200行
- 函数 ≤ 30行
- composable ≤ 150行
- api 文件 ≤ 50行
- controller ≤ 150行

请根据以上约束生成代码。如果约束与功能冲突，优先拆分文件/提取函数，不要违反约束。
```

**使用方法**：
- 每次开新的 AI 对话 → 先把 `anti-pattern-preface.md` 内容贴进去 → 再描述需求

## 四、第三层：人工约束（流程强制）

### 4.1 AI 交互 SOP（标准操作流程）

**每次让 AI 写/改代码时，按这个顺序执行**：

```
STEP 1: 贴反模式清单（30秒）
  → 打开 .trae/prompt-templates/anti-pattern-preface.md
  → 复制粘贴到 AI 对话

STEP 2: 描述需求（1分钟）
  → 明确：改哪个文件、做什么、不做什么
  → 强调："一次只改1-2个文件"

STEP 3: AI 生成代码后 → 立即执行检查清单（2分钟）
  → 打开 .trae/documents/代码生成后检查清单.md
  → 逐项打勾确认

STEP 4: 有违规 → 让 AI 修正 / 无违规 → 合入
```

### 4.2 代码生成后检查清单

**文件**：`.trae/documents/代码生成后检查清单.md`

```markdown
# 代码生成后检查清单

每次 AI 生成完代码，花 2 分钟逐项检查：

## 文件规模
- [ ] .vue 文件 ≤ 200行？
- [ ] 函数 ≤ 30行？
- [ ] composable ≤ 150行？
- [ ] api 文件 ≤ 50行？

## 架构分层
- [ ] 视图层没有直接 import axios？
- [ ] 视图层没有直接 import sse.js？
- [ ] 业务逻辑在 composable 里，不在组件里？

## 反模式
- [ ] 没有 async 函数漏 try-catch？
- [ ] timer/SSE/AbortController 有 onUnmounted 清理？
- [ ] 没有超过3行的数据转换在组件内？

## SSE 相关（如涉及）
- [ ] SSE 数据格式是三段式？
- [ ] Token 通过 Header 传递（POST）？
- [ ] 错误降级有3层？

## 一致性
- [ ] 新增接口完成了 controller → routes → api 三部曲？
- [ ] 没有跨 store 引用？
```
