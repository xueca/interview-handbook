## P0（扛不住直接挂 —— 4问）

### Q1：你介绍一下这个项目，用了哪些技术，为什么要选这些技术？

- **来源文件**：`frontend/package.json` / `backend/package.json`
- **一句话核心**：一个前后端分离的前端面试刷题平台，Vue3+Express+DeepSeek，核心卖点是AI实时流式出题和错题本的三次答对自动移除。

**回答框架**：
1. **项目定位**：不是创业产品，是"给自己用的学习工具"+"展示前端工程能力的作品"。定位说清楚，面试官就不会按商业产品标准审你。
2. **技术选型逻辑**：Vue3（Composition API，Vue生态最主流）+ Element Plus（国内最常用UI库）+ Pinia（Vue官方推荐）+ Express（轻量，不需要Spring那么重）+ DeepSeek（性价比最高的国产大模型，API兼容OpenAI格式，迁移成本为零）。
3. **数据存储为什么是JSON**：主动承认这不是生产方案，但说清楚理由——单人使用、零部署依赖、不需要装MySQL、重启不丢数据。面试官问这个不是要你认错，是要你证明你想过这个问题。

**追问风险**："JSON文件有什么问题？如果多人用怎么改？" → 并发写冲突（Node单线程但多次请求间无锁），迁移到SQLite/MongoDB的方案。

### Q2：SSE流式出题是怎么实现的？全流程说一下。

- **来源文件**：`backend/controllers/aiController.js` / `frontend/src/api/sse.js` / `frontend/src/composables/useAiChat.js`

**一句话核心**：前端用fetch+ReadableStream逐块读取，后端用Node的https.request流式转发DeepSeek的SSE，中间加了一个事件解析层把原始chunk转成结构化消息。

**回答框架**：
1. **数据流**：用户输入 → composable(useAiChat.js) → api/sse.js → POST到后端 → 后端转发DeepSeek → Stream返回 → 逐块解析 → 前端实时渲染
2. **为什么不用EventSource**：EventSource只能GET，我们要POST传参，所以用了fetch+ReadableStream+AbortController
3. **三个状态**：`status: thinking`（AI思考动画）、`content`（文本流）、`status: done`（流结束，触发JSON解析）
4. **流程完成后**：流结束后对完整文本做tryParseQuestion，识别是普通文本还是结构化题目

**追问风险**："SSE和WebSocket区别？" → SSE单向（服务器→客户端），WebSocket双向。AI出题不需要双向，选SSE更轻量。"流断了？" → 自动重试一次，失败降级为非流式。

### Q3：AI生成的JSON经常格式不稳定，你怎么处理的？

- **来源文件**：`backend/controllers/aiParser.js` / `backend/controllers/aiPrompt.js`

**一句话核心**：三层防御——Prompt约束输出格式 + 后端JSON修复（括号补全） + 前端二次解析（markdown代码块提取+字段校验）。

**回答框架**：
1. **Prompt层**：systemPrompt明确要求"返回纯JSON，不加markdown标记"，把题库最近30道题作为负面例子避免重复
2. **后端repairJSON**：AI返回了```json标记→strip掉；JSON括号不完整→统计`{`和`[`的开口数，自动补全
3. **前端tryParseQuestion**：先JSON.parse直接解析→失败则正则提取markdown代码块→字段校验（必须有title/options/answer）→校验不过降级为普通文本
4. **DeepSeek V4特殊处理**：parseStreamChunk中过滤reasoning_content（思维链输出），只取delta.content

**追问风险**："如果三层都失败？" → 降级为普通文本消息展示，不崩溃。

### Q4：JWT认证是怎么做的？token存在哪里？有什么安全问题？

- **来源文件**：`backend/controllers/authController.js` / `backend/middleware/auth.js` / `frontend/src/stores/user.js` / `frontend/src/router/index.js`

**一句话核心**：登录时后端用bcrypt验证密码、jwt签发7天有效token、存localStorage、每次请求带Authorization头、路由守卫拦截未登录访问。

**回答框架**：
1. **注册/登录流程**：密码用bcrypt(10轮加盐)哈希存users.json；登录比对hash→签发JWT(含id+username，7天过期)；注册成功后直接签发token
2. **请求认证**：axios拦截器从localStorage读token→自动带`Authorization: Bearer xxx`；后端auth中间件jwt.verify校验→挂到req.user
3. **路由守卫**：router.beforeEach检查localStorage有无token→无就重定向到/login；quiz页无参数→重定向到题库
4. **安全性权衡**：主动承认localStorage有XSS风险（但本项目无富文本渲染，风险可控）；密码要求字母+数字双因子；登录注册有IP级别限流

**追问风险**：100%追问"localStorage存token有什么问题？" → XSS可以读localStorage。httpOnly Cookie更安全但不能被JS读取，SPA不方便。可以提refresh token方案但本项目规模不需要。

## P1（答得好加分 —— 5问）

### Q5：错题本的"连续答对3次自动移除"是怎么实现的？

- **来源文件**：`backend/controllers/recordController.js`（calcConsecutive + getWrong）

**一句话核心**：每次提交时计算每道题的consecutiveCorrect（答对+1、答错归零），查询时过滤掉consecutiveCorrect>=3的题。

**回答框架**：
1. **计算时机**：每次提交通历所有历史记录（倒序），找该题上一次的consecutiveCorrect值，答对+1，答错归零
2. **数据存储**：存在records.json每条detail里，不单独开表
3. **查询过滤**：两步——先按整条历史标记everWrong，再查最新consecutiveCorrect，<3才进错题本，>=3计入已掌握
4. **边界处理**：错题本重做source标记为'wrong-book'，不计入答题统计

**追问风险**："做对了3次又做错？" → consecutiveCorrect归零，everWrong已经是true，题重新回错题本。

### Q6：你的项目代码是怎么分层的？为什么这么分？

- **来源文件**：`.trae/rules/01-architecture-contract.md`

**一句话核心**：views(UI) → composables(业务逻辑+状态) → api(HTTP) → backend，单向数据流，每层只做自己该做的事。

**回答框架**：
1. **四层架构**：视图层(只渲染和事件转发) → composable层(业务逻辑、状态管理、资源清理) → api层(只封装HTTP) → 后端(routes→controllers→data)
2. **为什么禁止view里写fetch**：为了可维护性——今天这个组件直调API，明天那个也直调，API地址一改要改10个文件。统一走api层改一个文件就行
3. **composable优势**：timer清理、SSE abort、localStorage读写集中管理，onUnmounted自动清理
4. **文件行数限制**：.vue≤200行、.js≤150行、函数≤30行——自己定的工程纪律，防止文件失控

**追问风险**："你作为大三学生怎么想到做分层约束？" → 直接说是AI辅助建立的项目规范，但自己理解了每层为什么这样设计。

### Q7：统计仪表盘的数据是怎么算出来的？

- **来源文件**：`backend/controllers/recordController.js`（getStats）/ `frontend/src/views/Dashboard.vue`

**一句话核心**：后端从records.json按用户ID过滤后，分"题目维度"（去重）和"会话维度"（按场次）统计，前端ECharts渲染三个图表。

**回答框架**：
1. **题目维度（去重）**：aggregateByQuestion遍历所有记录，同一题保留最后一次，算出总答题数、正确数、分类正确率、薄弱TOP5
2. **会话维度（按场次）**：排除错题本重打(source !== 'wrong-book')，统计答题次数和平均分；buildDailyTrend分组最近7天每日正确率
3. **前端三个图表**：折线图(每日趋势)、柱状图(分类正确率)、饼图(薄弱TOP5)。暗黑模式销毁重建实例而非只改配置
4. **为什么分开两个维度**：题目维度反映真实掌握水平(每题只看最近)，会话维度反映刷题活跃度

### Q8：聊一下状态管理方案？Pinia和Vuex有什么区别？

- **来源文件**：`frontend/src/stores/*.js` / `frontend/src/composables/useAiChat.js`

**一句话核心**：Pinia管全局共享状态（token、统计数据），composable管页面级状态（答题、AI对话），互不越界。

**回答框架**：
1. **为什么Pinia不是所有状态都管**：userStore和recordStore跨页面共享→Pinia；useQuiz答题进度、useAiChat消息列表只在单页用→composable
2. **Pinia vs Vuex**：Pinia是Vuex5的正式替代，支持Composition API写法（setup store），不需要mutations，模块不需要嵌套
3. **composable优势**：把timer、SSE、localStorage的副作用和清理逻辑封装在一起，onUnmounted自动清理
4. **模块级变量的坑**：禁止在.js顶层写`let currentStream = null`这种共享状态，组件卸载后状态残留会内存泄漏

**追问风险**："Vue的响应式原理是什么？" → 高频追问。准备ref/reactive区别、computed缓存机制、watch的deep选项。

### Q9：怎么保护前端路由？用户直接在地址栏输入路径会怎样？

- **来源文件**：`frontend/src/router/index.js`

**一句话核心**：router.beforeEach全局前置守卫检查token，无token→登录页；quiz页无参数→题库；双层防护（前端+后端）。

**回答框架**：
1. **守卫逻辑**：每次跳转前检查to.name !== 'Login'且无token → 强制定向/login
2. **双层防护**：前端守卫是第一层（用户体验）；后端auth中间件是第二层（安全，每个API都验证token，绕过前端也拿不到数据）
3. **quiz特殊处理**：无ids也无category/difficulty参数→踢回题库
4. **为什么不做角色权限**：单人项目，RBAC是过度设计

**追问风险**："前端路由守卫能被绕过吗？" → 能，禁JS或改localStorage就行。所以后端每个接口都必须验证。强调"双层防护"。

## P2（锦上添花 —— 3问）

### Q10：暗黑模式怎么实现的？ECharts怎么跟着变？

- **来源文件**：`frontend/src/composables/useDarkMode.js` / `frontend/src/views/Dashboard.vue`

**一句话核心**：document.documentElement切换`dark` class，配合CSS变量让Element Plus自动切换；ECharts销毁实例再重建。

**回答框架**：Element Plus自带暗黑支持+html上`dark` class自动切换；状态存localStorage；ECharts不支持运行时切换主题→watch isDark→dispose三个实例→重新init；darkColors computed根据isDark返回不同颜色。

### Q11：登录/注册怎么防暴力破解？

- **来源文件**：`backend/middleware/rateLimit.js`

**一句话核心**：基于IP+路径的内存限流，15分钟窗口内最多10次，超出返回429+剩余等待秒数。

**回答框架**：固定时间窗算法用Map存key(IP:路径)→{count, resetAt}；Map超5000条惰性清理过期key；为什么不用Redis→项目轻量不额外部署依赖，单进程Express够用。

### Q12：为什么选DeepSeek而不是ChatGPT？

- **来源文件**：`backend/controllers/aiController.js`

**一句话核心**：API兼容OpenAI格式零迁移成本、中文能力强、价格便宜适合个人项目。

**回答框架**：完全兼容OpenAI chat/completions格式→想换模型只改一行URL和key；前端面试题是中文内容，国产模型中文理解更好；成本低；已处理R1推理模型的reasoning_content过滤。
