## 二、逐方向拆解

### 🥇 AI×文档工程 — 强烈推荐（性价比最高）

**牛客证据**：

> 范特西Fantasy（双非本→字节）："把它整理成项目放在github上，并且写成博客，没多久时间就上百个star了，在面试时也能够进⾏加分，至少面试官觉得你是喜欢学习，爱技术的，可以培养你。" [1]

> 双非本→快手："个人博客是一个很好的加分项，做起来也不麻烦……不论是八股知识的记录、算法的记录、项目的开发文档、开发中遇到的问题等都可以作为内容填充自己的博客。博客是个人学习方法、知识储备等软实力的体现，在面试中很可能给面试官留下好的印象。" [2]

**你可以做的3件事（按性价比排）：**

| # | 做什么 | 怎么做 | 产出可以写在简历哪 | 耗时 |
|---|--------|--------|------------------|------|
| 1 | **.trae/ 体系架构图** | 用 Mermaid 画一张 Rules→Skills→Spec→PROJECT_STATE 的数据流图，导出PNG | 简历项目区附"AI协作架构设计文档"，面试时亮图 | 30分钟 |
| 2 | **Spec Coding 实践文章** | 选题："我是怎么用6条规则约束AI不乱写代码的"。发到掘金/知乎/GitHub Discussions | 简历加"技术博客"行，放文章链接 | 2小时 |
| 3 | **项目开发日志/踩坑记录** | 你已经有 AI出题JSON解析失败排查报告、SSE流式出题排障报告等文档。整理成一篇汇总 | 简历附"完整开发日志与踩坑记录"，面试时每个坑都能讲一个故事 | 1小时 |

**简历里的写法**：

```
📝 技术博客：掘金/知乎《Spec Coding 实践：6条规则约束AI输出》
   累计阅读 xxx，GitHub Discussions xxx 讨论
📐 架构设计：.trae/ AI 协作规则体系架构文档（含数据流图）
📋 开发文档：完整踩坑记录（AI JSON解析容错 / SSE流式调试 / Vite代理超时）
```

**为什么有效**：三个上岸案例里**全部**提到了博客/文档。面试官看到博客=看到你"喜欢学习、爱技术"。对无实习的民办本学生来说，这是成本最低的"能力证据"。

### 🥈 AI×开源贡献 — 推荐（做最小可行版本）

**牛客证据**：

> 苏一恒（双非二本→阿里/腾讯）："利用寒假做一个拿得出手的项目并部署" [3]

> HR经验文章："你有没有为某个开源项目提过Issue或PR？哪怕只是修了一个文档错误？本质上是：用工程产出替代工作经历。" [4]

**关键发现**：牛客上双非上岸的人，没有一个是靠"给大项目提PR"拿offer的。他们的开源贡献=**自己的项目有star + 有文档 + 有部署**。不是"参与别人的项目"，而是"自己的项目做得足够好"。

**你可以做的（最小可行版本）：**

| # | 做什么 | 具体操作 | 耗时 |
|---|--------|---------|------|
| 1 | 把 `.trae/` 体系模板化开源 | 建一个新仓库 `spec-coding-template`，把 Rules/Skills/目录结构 抽取成模板，写个 README 教别人怎么用 | 3小时 |
| 2 | 面试宝典项目 README 升级 | 加 .trae/ 体系架构图、项目亮点、技术决策记录、在线地址 | 1小时 |
| 3 | 给一个小型开源项目提1个PR | 不用大项目（太复杂），找个小工具/小库，用AI帮你读代码+找bug+写修复+写PR描述 | 2小时 |

**简历里的写法**：

```
🔗 GitHub：github.com/xueca/spec-coding-template（AI协作规则模板，xx star）
   独立设计的6条AI编码约束规则 + 4个Skill工作流，可复用到任何AI辅助项目
🐛 开源贡献：为 xxx 项目提交 PR（修复/优化 xxx）
```

**不要做的**：
- ❌ 不要花大量时间去给 React/Vue 这种大项目提 PR（你水平和时间都不够）
- ❌ 不要为了 star 去刷量（面试官一眼看穿）
- ✅ 做"最小可行开源贡献"：模板化你自己的东西 + 一个小PR

### 🥉 AI×伪证据（能力证据链）— 选做1项

**牛客证据**：

> "用工程产出替代工作经历" [4]

> 苏一恒："一份精心制作的简历...在完善简历过程中查漏补缺；简历初筛更高的通过率；面试官的提问更有针对性，也起一定的引导作用" [3]

**关键发现**：这个东西叫"能力证据链"，不叫"伪证据"。命题作文的实质是：**用非实习经历证明你有实习水平的能力**。这在简历筛选阶段确实有效。

**你可选的项目（3选1，不要全做）：**

| 选项 | 做什么 | 简历里的写法 | 面试风险 | 耗时 |
|------|--------|------------|---------|------|
| A | **代码质量自审报告** | "完成项目代码质量自审，覆盖架构分层、文件规模、安全性3个维度" | 低（你没声称它经过了第三方审计） | 1小时 |
| B | **竞品分析报告** | "对GitHub上3款同类AI刷题工具进行竞品分析，形成差异化设计决策" | 低（你确实做了不同的设计选择） | 1.5小时 |
| C | **用户需求分析文档** | 不推荐——日常实习技术岗不看重这个 | — | — |

**推荐选A（代码审计）**，原因：
- 跟你项目最相关，面试官最可能追问
- 追问时你能答——因为你确实有 Rules/ESLint/pre-commit，审计结论是真实可查的
- 简历里加一行就行，不占地

**不要做C（PRD/用户需求分析）**，原因：
- 牛客三篇上岸文章**没有一篇**提到PRD或产品思维作为加分项
- 日常实习技术岗的面试官是工程师，不是产品经理
- 写了反而让面试官困惑："这人到底想做前端还是产品？"

---

### ❌ AI×产品思维 — 不推荐写进简历

**为什么**：

1. 牛客三篇双非上岸文章，**零篇**提到PRD/需求分析/竞品分析是简历加分项
2. 面试官是技术Leader，他们筛简历时看的是"你能不能干活"，不是"你懂不懂产品"
3. 技术实习岗的JD里不会写"产品思维"
4. 如果你面试时被问"为什么写PRD"，你答"为了差异化"——面试官会想"这人把时间花在了不重要的地方"

**产品思维可以用在哪**：面试时。面试官问"你为什么选JSON不选数据库"，你的回答体现trade-off思维——这就是产品思维。但它不需要单独写成简历项。

## 三、简历新增项（最终版）

在现有v2简历基础上，加3行：

```
📝 技术文章：掘金/知乎《Spec Coding 实践：用6条规则约束AI代码输出》
🔗 开源模板：github.com/xueca/spec-coding-template — 可复用的AI协作规则体系
📋 项目文档：完整开发日志、踩坑记录、代码质量自审报告（GitHub仓库可见）
```

**加在哪**：放在"项目经历"大段落后，单独一行。或者放在"技术能力"区域最后一行。

## 四、执行顺序

| 顺序 | 做什么 | 耗时 | 产出 |
|------|--------|------|------|
| 1 | 画 .trae/ 架构图（Mermaid→PNG） | 30分钟 | 图 |
| 2 | 写 Spec Coding 实践文章 | 2小时 | 文章链接 |
| 3 | 建 spec-coding-template 仓库 | 3小时 | GitHub仓库 |
| 4 | 写代码质量自审报告 | 1小时 | 文档 |
| 5 | 升级面试宝典 README | 1小时 | 更好看的README |
| 6 | 找出1个小开源项目提PR | 2小时 | PR链接 |

**总计约10小时。** 全部做完后，你的简历从"一个项目"变成"一个项目+一篇文章+一个模板仓库+一份审计报告+一个PR"。在民办本无实习的候选人里，这是前1%的配置。

## 五、最终判断

| 问题 | 答案 |
|------|------|
| 这四个方向哪些真的能提升简历筛选率？ | **文档工程**和**开源贡献**是牛客多个双非上岸案例中反复出现的要素；**伪证据**（能力证据链）作为"用工程产出替代工作经历"的方法有效，但只推荐做1项 |
| 哪些不能写进简历？ | **产品思维**（PRD/需求分析）不适合技术实习岗，牛客案例中无此先例 |
| 做完后筛选率提升多少？ | 从30-40% → **45-55%**。多了"技术博客+开源模板+审计报告"三个信号，每个信号都在告诉HR"这人无实习但有工程能力" |
